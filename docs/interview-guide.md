# FinanceFlow: как разобраться в проекте и показать его

Этот материал помогает объяснять реальные решения в коде. Он не означает, что ты уже знаешь каждую тему. Открой упомянутый файл, измени пример и посмотри, что произойдёт.

## Как устроено приложение

`main.tsx` подключает React, StrictMode, BrowserRouter и ErrorBoundary. В `App.tsx` живут общие операции, бюджеты и настройки. Страницы получают их через props, а изменения возвращают через функции. Отдельный черновик формы существует только пока открыт диалог. Итоги, графики и прогресс бюджетов вычисляются из общего массива, поэтому их не нужно синхронизировать вручную.

`useStoredState` читает localStorage при создании состояния и записывает изменения через effect. Сначала JSON проходит runtime-проверку. Если исходное сохранение повреждено, автоматическая запись блокируется до явного сброса. `useExchangeRate` отдельно получает справочный курс, отменяет запрос при cleanup и сохраняет последний успешный результат. Денежные данные никогда не отправляются API.

Можно было использовать Context или внешний store, но для пяти страниц достаточно общего родителя. Можно было писать графики вручную, но Recharts уже решает масштабирование и адаптивность. Можно было использовать сервер, но это изменило бы задачу: появились бы аккаунты, синхронизация и защита серверных данных.

## 40 вопросов с привязкой к коду

### 1. Чем state отличается от props?

**Коротко:** state принадлежит компоненту, props приходят от родителя.

`App` хранит операции, а `Dashboard` получает их. Страница не меняет полученный массив: она вызывает переданную функцию. Это делает направление данных понятным. Местное состояние `filters` принадлежит странице Transactions, потому что другим страницам оно не нужно.

Код: [App.tsx](../src/App.tsx), [Transactions.tsx](../src/pages/Transactions.tsx).

### 2. Что такое derived state?

**Коротко:** значение, которое можно посчитать из уже существующих данных.

Баланс — сумма доходов минус расходы. Если хранить баланс отдельным state, можно забыть обновить его при удалении операции. `totals` пересчитывает его из массива при рендере. Для небольшого списка это достаточно быстро без useMemo.

Код: [finance.ts — totals](../src/utils/finance.ts), [SummaryCards.tsx](../src/components/SummaryCards.tsx).

### 3. Зачем поднимать состояние к общему родителю?

**Коротко:** чтобы несколько страниц работали с одной версией данных.

Одна и та же операция влияет на Dashboard, Budget и Statistics. Состояние в каждой странице создало бы независимые копии. В App данные меняются один раз, после чего React передаёт новое значение всем нужным компонентам.

Код: [App.tsx — transactionProps и маршруты](../src/App.tsx).

### 4. Что такое controlled input?

**Коротко:** поле, значение которого задаёт React state.

`value={amount}` показывает текущую строку, а onChange сохраняет ввод. Сумма остаётся строкой до отправки: так можно набрать запятую, увидеть ошибку и исправить промежуточное значение. Преобразование происходит в submit.

Код: [TransactionForm.tsx](../src/components/TransactionForm.tsx).

### 5. Почему используются form и preventDefault?

**Коротко:** form даёт стандартное поведение отправки, preventDefault отменяет навигацию браузера.

Пользователь может отправить форму кнопкой или Enter. Обработчик валидирует ввод и меняет React state без перезагрузки страницы. У Cancel указан `type="button"`, иначе внутри формы он тоже мог бы отправить её.

Код: [TransactionForm.tsx — submit](../src/components/TransactionForm.tsx).

### 6. Зачем React нужны keys?

**Коротко:** чтобы сопоставлять элементы между рендерами.

В таблице ключом служит постоянный id. После фильтрации или сортировки позиция меняется, но id остаётся. Индекс не описывает личность операции и может приводить к неправильному сохранению состояния дочерних компонентов.

Код: [TransactionTable.tsx](../src/components/TransactionTable.tsx).

### 7. Почему нельзя мутировать state?

**Коротко:** новое значение должно иметь понятную новую ссылку.

Редактирование создаёт новый массив через map, удаление — через filter. Это сохраняет предыдущую версию данных и позволяет React корректно заметить изменение. Изменение `transaction.amountCents` напрямую могло бы затронуть объект, который используют другие компоненты.

Код: [App.tsx — saveTransaction](../src/App.tsx).

### 8. Когда нужен функциональный setter?

**Коротко:** когда новое состояние зависит от предыдущего.

`transactions.update(current => ...)` работает с актуальным массивом, который React передаст updater-функции. Это безопаснее, чем собирать обновление из переменной старого рендера, особенно когда несколько изменений стоят в очереди.

Код: [App.tsx — saveTransaction](../src/App.tsx).

### 9. Чем map, filter и reduce отличаются?

**Коротко:** map преобразует, filter отбирает, reduce собирает итог.

map заменяет редактируемую операцию; filter выбирает нужный месяц; reduce складывает суммы. Они подходят для небольших чистых функций. Метод sort, напротив, мутирует массив, поэтому здесь он применяется к новому результату filter.

Код: [finance.ts — inMonth, totals, filterTransactions](../src/utils/finance.ts).

### 10. Как сделать сортировку без изменения исходных данных?

**Коротко:** сортировать копию или результат метода, создающего новый массив.

filterTransactions сначала вызывает filter, затем sort. При равенстве comparator возвращает 0 и сохраняется относительный порядок равных элементов. Для даты подходит строковое сравнение, потому что формат всегда YYYY-MM-DD.

Код: [finance.ts — filterTransactions](../src/utils/finance.ts).

### 11. Для чего нужен useEffect?

**Коротко:** синхронизировать компонент с внешней системой.

Запись в хранилище, сетевой запрос и обработчики window относятся к внешним системам. Расчёт суммы — нет: он выполняется обычной функцией во время рендера. Effect не должен превращаться в способ вручную синхронизировать все вычисляемые значения.

Код: [useStoredState.ts](../src/hooks/useStoredState.ts), [useOnline.ts](../src/hooks/useOnline.ts).

### 12. Что такое cleanup?

**Коротко:** функция, отменяющая работу предыдущего effect.

useOnline удаляет те же обработчики, которые добавил. useExchangeRate отменяет fetch и таймер. Без cleanup после размонтирования могли бы оставаться слушатели и устаревшие запросы.

Код: [useOnline.ts](../src/hooks/useOnline.ts), [useExchangeRate.ts](../src/hooks/useExchangeRate.ts).

### 13. Почему важны зависимости effect?

**Коротко:** они определяют, когда внешнюю синхронизацию нужно повторить.

Запись в storage зависит от ключа, данных и флага блокировки. Запрос курса зависит от номера повторной попытки. Если забыть зависимость, effect может использовать устаревшее значение; если добавить нестабильный объект без причины, запросы могут повторяться слишком часто.

Код: [useStoredState.ts](../src/hooks/useStoredState.ts), [useExchangeRate.ts](../src/hooks/useExchangeRate.ts).

### 14. Что проверяет StrictMode?

**Коротко:** помогает заметить нечистые рендеры и неправильный cleanup в разработке.

React может повторно выполнить цикл setup/cleanup. Диалог обязан корректно открываться после закрытия, а первый запрос — отменяться. Не нужно выключать StrictMode, чтобы скрыть двойной запрос в режиме разработки.

Код: [main.tsx](../src/main.tsx), [Dialog.tsx](../src/components/Dialog.tsx).

### 15. Чем useRef отличается от useState?

**Коротко:** изменение ref не вызывает рендер.

Ref хранит ссылку на HTMLDialogElement. Она нужна для `showModal`, `close` и фокуса. Поля формы, напротив, находятся в state, потому что их изменения должны отражаться в интерфейсе.

Код: [Dialog.tsx — ref](../src/components/Dialog.tsx).

### 16. Где здесь прямой доступ к DOM?

**Коротко:** там, где необходимо управлять нативным диалогом и фокусом.

Код читает activeElement, вызывает focus и методы dialog. Он не меняет вручную содержимое таблицы: её рисует React. Это разделяет декларативное представление данных и ограниченные императивные действия браузера.

Код: [Dialog.tsx](../src/components/Dialog.tsx).

### 17. Что такое всплытие событий?

**Коротко:** событие от дочернего элемента может пройти к его предкам.

Клик по SVG внутри кнопки попадает в обработчик кнопки. В таблице нет обработчика на всю строку, поэтому Edit и Delete не конфликтуют с кликом строки. stopPropagation здесь не нужен; его стоит добавлять только для конкретного конфликта.

Код: [TransactionTable.tsx — rowActions](../src/components/TransactionTable.tsx).

### 18. Почему native dialog удобнее самодельного div?

**Коротко:** браузер уже умеет модальность, ограничение фокуса и Escape.

showModal помещает окно в верхний слой. Обработчик cancel связывает Escape с React state. Cleanup возвращает фокус на кнопку открытия, а если она удалена — на заголовок страницы. Браузерный тест проверяет реальный Tab, а DOM-мок этого не доказывает.

Код: [Dialog.tsx](../src/components/Dialog.tsx), [app.spec.ts](../e2e/app.spec.ts).

### 19. Зачем семантические HTML-элементы?

**Коротко:** они объясняют назначение частей страницы браузеру и вспомогательным технологиям.

header, nav, main, table и form несут смысл. Ссылки переходят между страницами, кнопки выполняют действия. Подписи label связываются с вложенными полями, а aria-describedby добавляет объяснение ошибки.

Код: [App.tsx](../src/App.tsx), [TransactionForm.tsx](../src/components/TransactionForm.tsx).

### 20. Что дают CSS Modules?

**Коротко:** локальные имена классов без ручного придумывания уникальных префиксов.

Импорт styles превращает локальные названия в сгенерированные классы. Общие переменные цветов остаются глобальными, потому что ими пользуется всё приложение. Модуль не делает CSS автоматически качественным: структура и повторное использование всё равно важны.

Код: [ui.module.css](../src/components/ui.module.css), [App.module.css](../src/App.module.css).

### 21. Как устроены темы и адаптивность?

**Коротко:** темы меняют CSS-переменные, media queries меняют раскладку.

App задаёт `data-theme` корневому элементу. Переменные отвечают за фон, текст и границы. На телефоне боковая навигация становится нижней, а таблица прокручивается в своём контейнере. Переполнение страницы и локальная прокрутка таблицы — разные вещи.

Код: [global.css](../src/styles/global.css), [App.module.css](../src/App.module.css), [ui.module.css](../src/components/ui.module.css).

### 22. Что происходит при переходе по React Router Link?

**Коротко:** меняется маршрут и содержимое приложения без полной загрузки документа.

BrowserRouter использует History API. Routes выбирает элемент по пути, NavLink отмечает активную страницу. При прямом открытии вложенного URL сервер всё равно должен вернуть index.html; это настраивает `_redirects`.

Код: [main.tsx](../src/main.tsx), [App.tsx](../src/App.tsx), [\_redirects](../public/_redirects).

### 23. Чем interface отличается от реальной проверки данных?

**Коротко:** TypeScript проверяет код до выполнения, но не содержимое внешнего JSON.

Ответ сервера и localStorage могут содержать что угодно. Поэтому JSON сначала имеет тип unknown. Функции isTransaction и isExchangeRate проверяют значения во время работы и только затем позволяют использовать нужный тип.

Код: [types.ts](../src/types.ts), [storage.ts](../src/services/storage.ts).

### 24. Почему unknown лучше any на границе API?

**Коротко:** unknown заставляет проверить данные перед доступом к полям.

any отключил бы эту защиту. Type guard с результатом `value is ExchangeRate` сообщает компилятору, что после успешной проверки доступны нужные поля. Сам type guard тоже может быть неверным, поэтому его важные условия покрыты тестами.

Код: [storage.ts — isExchangeRate](../src/services/storage.ts), [exchangeRates.ts](../src/services/exchangeRates.ts).

### 25. Как работает localStorage?

**Коротко:** синхронное хранилище строк, отдельное для каждого origin.

Массив превращается в строку через JSON.stringify, а обратно — через JSON.parse. Данные сохраняются между посещениями, но могут исчезнуть после очистки браузера. Хранилище ограничено по размеру и не является облачной резервной копией.

Код: [storage.ts — readStored, writeStored](../src/services/storage.ts).

### 26. Зачем ленивая инициализация state?

**Коротко:** чтобы прочитать начальное значение при создании состояния, а не при каждом рендере.

`useState(() => readStored(...))` восстанавливает данные до первого effect записи. Сохранённый `[]` считается валидным состоянием, а не поводом вернуть демо. Проверять нужно отсутствие ключа, а не длину массива.

Код: [useStoredState.ts](../src/hooks/useStoredState.ts), [storage.test.ts](../src/services/storage.test.ts).

### 27. Как обрабатывается повреждённое сохранение?

**Коротко:** показывается предупреждение, запись блокируется до подтверждённого сброса.

Автоматически перезаписать сломанный JSON демонстрационными данными было бы потерей оригинала. Hook позволяет работать с временным состоянием в памяти. Пользователь может явно сбросить только нужный набор в Settings.

Код: [storage.ts](../src/services/storage.ts), [useStoredState.ts](../src/hooks/useStoredState.ts), [Settings.tsx](../src/pages/Settings.tsx).

### 28. Что относится к Browser APIs и BOM?

**Коротко:** возможности браузера вокруг JavaScript: window, navigator, storage, таймеры и другие API.

useOnline читает navigator.onLine и подписывается на window events. Этот флаг сообщает о сетевом подключении, но не доказывает доступность конкретного сервера. Поэтому сетевой запрос имеет свою обработку ошибок.

Код: [useOnline.ts](../src/hooks/useOnline.ts), [useExchangeRate.ts](../src/hooks/useExchangeRate.ts).

### 29. Что такое Promise и async/await?

**Коротко:** Promise представляет будущий результат, await позволяет дождаться его в async-функции.

fetch возвращает Promise<Response>, а response.json — ещё один Promise. Ожидание не блокирует пользовательский ввод. Исключение из любого шага попадает в catch вызывающей async-функции.

Код: [exchangeRates.ts — fetchExchangeRate](../src/services/exchangeRates.ts), [useExchangeRate.ts](../src/hooks/useExchangeRate.ts).

### 30. Почему fetch не достаточно обернуть только в catch?

**Коротко:** HTTP 404 или 503 сами по себе не отклоняют Promise fetch.

Нужно проверить response.ok и самостоятельно бросить ошибку для неуспешного статуса. После этого требуется проверить JSON: успешный HTTP ещё не означает корректную структуру данных.

Код: [exchangeRates.ts](../src/services/exchangeRates.ts), [exchangeRates.test.ts](../src/services/exchangeRates.test.ts).

### 31. Что означает REST API в этом проекте?

**Коротко:** клиент делает HTTP GET к публичному ресурсу и получает JSON.

В URL указана пара USD/EUR. Ответ содержит базовую валюту, целевую валюту, дату и курс. Проект использует только чтение публичного ресурса; операции пользователя через этот API не сохраняются. CORS разрешает браузеру читать ответ другого origin.

Код: [exchangeRates.ts — exchangeRateUrl](../src/services/exchangeRates.ts).

### 32. Как избежать устаревшего ответа запроса?

**Коротко:** отменить предыдущий запрос и не применять результат завершённого effect.

AbortController передаёт signal в fetch. Cleanup выставляет active=false и отменяет запрос. Даже если Promise завершится почти одновременно, проверка active не позволит старому effect обновить state. Таймер ограничивает ожидание.

Код: [useExchangeRate.ts](../src/hooks/useExchangeRate.ts).

### 33. Что делать, если API курса недоступен?

**Коротко:** показать сохранённый проверенный курс или честно оставить USD.

Нельзя просто подписать долларовую сумму как евро. Hook хранит последний успешный курс с датой; App выбирает фактическую валюту отображения. В Settings есть Retry и объяснение, что курс справочный, а не торговый в реальном времени.

Код: [useExchangeRate.ts](../src/hooks/useExchangeRate.ts), [App.tsx — money](../src/App.tsx), [Settings.tsx](../src/pages/Settings.tsx).

### 34. Почему деньги хранятся в центах?

**Коротко:** целые значения избегают обычной погрешности дробного сложения.

Строка `12.34` разбирается на целую и дробную части, после чего получается 1234. Regex не разрешает экспоненту и лишние знаки. Number.isSafeInteger проверяет границу точного целого. Деление на 100 и округление для валюты относятся к отображению.

Код: [finance.ts — parseAmount](../src/utils/finance.ts), [finance.test.ts](../src/utils/finance.test.ts).

### 35. Почему календарная дата хранится строкой?

**Коротко:** операция относится к дню, а не к моменту времени в UTC.

YYYY-MM-DD удобно фильтровать по первым семи символам. Преобразование через UTC может сдвинуть день в другом часовом поясе. Для локального форматирования используется время 12:00 без Z, а today собирается из локальных частей даты.

Код: [finance.ts — today, isDate, formatDate, inMonth](../src/utils/finance.ts).

### 36. Как считается бюджет и почему spent не хранится отдельно?

**Коротко:** spent — сумма расходов нужной категории за выбранный месяц.

Доходы и другие месяцы исключаются. После изменения операции значение автоматически пересчитывается. Текстовый процент может превысить 100%, но CSS-ширина ограничена 100%, чтобы полоса не вышла из контейнера.

Код: [finance.ts — budgetSpent](../src/utils/finance.ts), [BudgetProgress.tsx](../src/components/BudgetProgress.tsx).

### 37. Почему график — это представление, а не отдельная база данных?

**Коротко:** графику передаются агрегаты исходных операций.

sixMonths создаёт шесть календарных месяцев, включая пустые. SpendingChart группирует расходы по категориям. Пользователь может прочитать те же суммы в таблице и списке; картинка не является единственным носителем информации.

Код: [finance.ts — sixMonths](../src/utils/finance.ts), [Charts.tsx](../src/components/Charts.tsx).

### 38. Какие ошибки ловит Error Boundary?

**Коротко:** ошибки рендера дочернего дерева, но не произвольные асинхронные ошибки или события.

Компонент показывает fallback вместо сломанного интерфейса. Ошибки fetch всё равно обрабатываются try/catch, а неверный ввод — в форме. Reload не очищает localStorage. Небольшой class component здесь выбран ради стандартного механизма React.

Код: [ErrorBoundary.tsx](../src/components/ErrorBoundary.tsx).

### 39. Чем отличаются unit, component и browser tests?

**Коротко:** они проверяют разные границы поведения.

Unit-тест проверяет parseAmount без браузера. Component-тест вводит текст и нажимает кнопку через Testing Library. Playwright запускает настоящее окно Chromium и проверяет полный путь пользователя, фокус и размеры. Сеть заменена mock-ответами для повторяемости; assertion проверяет наблюдаемый результат, а не CSS-класс.

Код: [finance.test.ts](../src/utils/finance.test.ts), [TransactionForm.test.tsx](../src/components/TransactionForm.test.tsx), [app.spec.ts](../e2e/app.spec.ts).

### 40. Как Git, lockfile и сборка помогают повторить результат?

**Коротко:** Git фиксирует исходники, lockfile — точные зависимости, build — воспроизводимый артефакт.

Перед коммитом полезно прочитать git diff и выполнить проверки. node_modules и dist не должны попадать в историю. npm ci устанавливает зависимости по lockfile. Публикация — отдельное действие: наличие dist не доказывает существование работающего сайта.

Код: [.gitignore](../.gitignore), [package.json](../package.json), [deployment.md](deployment.md).
